# Roadmap — from trading-specific skill to multi-domain advisor

Companion to `docs/design.md`, which records why v1 is built the way it is. This records where it
is going and why those choices.

## Target

A **configurable, multi-domain advisor**: reads documentation distilled from books, and applies the
knowledge of the *respective* book to the task at hand. Imports also accept research reports
(hyperresearch markdown). Distributed via git, with a bundle export for cloud runtimes.

## What already transfers

Measured, not assumed: the only occurrence of trading vocabulary in ~1,100 lines of `scripts/` is a
code comment explaining a bug fix. **The engine is already domain-agnostic.** Domain lock-in lives
entirely in prose and config:

```
SKILL.md 26 · conflicts.md 22 · taxonomy.json 18 · workflows.md 12 · README 10   (vocabulary hits)
```

Also generic and reusable as-is: pack kinds (`book`/`notes`/`engine`), the chapter and note
contracts, rule IDs, three-tier disclosure, byte-offset engine indexing, the inbox→notes→rules
import path, deterministic builds, the validator.

Roughly **70% of v1 survives**. The work is content extraction, configuration, and distribution.

## Architectural decisions

### D1 — One skill with a *generated* description

Rejected: one skill with a hand-written multi-domain description (triggers badly — the description
is the sole determinant of whether a skill fires); and a generator emitting one skill per domain
(sharp triggering, but N installs and no cross-domain reasoning).

**Chosen:** one skill, many domain packs, and the frontmatter `description` is **regenerated by
`build_index.py` from the installed domains**. The description stops being maintained prose and
becomes a build artifact. This dissolves the multi-purpose vs. triggering tension rather than
trading one off against the other.

### D2 — Single private monorepo

`github.com/trbck/advisor`, private, holding toolkit and domains together. Splitting toolkit from
corpora buys nothing for a single user and costs submodule ceremony. The domain manifest keeps
corpora isolated, so a split later is mechanical if the engine is ever open-sourced.

Privacy is load-bearing: distilled chapters are original summaries but derived from copyrighted
works, and `knowledge/*/vbtpro/*.txt` is licensed vendor documentation (gitignored regardless).

### D3 — Git primary, bundle as an export target

Not bundle *vs* git:

- **Primary** — git as master. `bin/advisor-sync` clones or pulls into `~/.claude/skills/advisor`
  on any machine with a shell.
- **Export** — `scripts/package_domain.py` emits a `.skill` bundle for cloud runtimes: one domain,
  books plus generated artifacts, **engine packs excluded**. Sizing today: 1.4 MB versus 22 MB.

**Accepted constraint:** ingestion writes files, so it needs write access. Cloud runtimes get a
read-only corpus; reports are ingested where there is write access, then pushed. Anything else
silently loses data.

### D4 — Refactor must preserve every rule ID

Phases 1–4 restructure the tree. A changed ID invalidates every citation already written, including
those in `references/conflicts.md`. `tests/rule-ids.baseline` pins all 551; the acceptance test for
each phase is an empty diff against it.

### Phase 1 — Domain manifest & extraction

```
domains/trading/
  domain.json      name, description, scope, modes, gates
  packs.json       taxonomy.json  conflicts.md
  knowledge/       ml4t/ assp/ notes/ vbtpro/
generated/trading/ ROUTER.md  rules/  engines/  index.json
```

`ka_common.py` gains domain resolution; `build_index.py` loops domains. Nothing else in `scripts/`
changes.

### Phase 2 — Generated skill surface

`SKILL.md` splits into `templates/SKILL.md.tmpl` plus generated output; the frontmatter description
is composed from each domain's `description` and `scope`; `references/workflows.md` is generated
from mode configuration.

### Phase 3 — Modes & gates as configuration

Default mode set, domain-overridable:

| Mode | Generic meaning | Trading instance |
|---|---|---|
| `research` | Grounded answer, conflicts surfaced | unchanged |
| `compare` | Contrast positions across packs | *new* |
| `plan` | Spec forced through domain **gates** | design a strategy |
| `produce` | Artifact plus compliance manifest | write the backtest |
| `review` | Artifact against a defect checklist | audit for lookahead bias |

ml4t's "five frozen choices" generalise to **gates** — a named checklist that must be answered
before work proceeds — declared in `domains/<id>/gates.json`.

### Phase 4 — Multi-domain routing — *delivered, with one simplification*

A separate `generated/DOMAINS.md` proved unnecessary: the generated `{{DOMAINS}}` table in
`SKILL.md` is always loaded and already serves as the domain index. One artifact fewer to keep in
sync.

Delivered: the validator enforces **globally unique pack prefixes** (two packs sharing one would
mint colliding rule IDs across domains); `lookup.py` merges all domain indexes and qualifies IDs as
`trading:ASSP-09-R7` **only when more than one domain is installed**, so single-domain citations
stay short. Verified end to end with a throwaway stub domain — cross-domain search, `--domain`
isolation, description regeneration, and collision rejection — then removed.

### Phase 5 — Bootstrapping tools

New-domain friction is what stops books getting added, so this is a feature, not polish.

- `suggest_taxonomy.py` — candidate topics and keywords from chapter titles and `Governs:` lines.
- `suggest_conflicts.py` — cross-pack rule pairs that are topically adjacent and lexically opposed
  (`never`/`always`, `prefer`/`avoid`), proposed for human confirmation.

### Phase 6 — Second domain: *Algorithms to Live By*

Chosen deliberately: decision-making and computer science, sharing almost no vocabulary with
trading. Any edit required to `scripts/` during this phase is a defect in Phases 1–5, not a task.

Watch specifically for: taxonomy assumptions, mode names that only make sense for strategies, gates
that presuppose a backtest, and the ID scheme.

## Sequencing

Phases 1–4 are one continuous block — stopping halfway leaves configuration split across two
idioms, and the ID baseline makes the block safe. Phase 6 is the honest test of genericity; resist
adding features until it passes.

## Open items carried from v1

- No evals (now Phase 8, and more important with a generated description).
- `--search` over-ranks chapter hits relative to rules.
- Topic classification is keyword-based; misfilings are cosmetic since IDs do not depend on topics.
- ml4t chapter 20 absent from the distilled set.
